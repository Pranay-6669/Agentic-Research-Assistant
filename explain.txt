1. What did we build?

We built an Agentic Research Assistant that can answer from two sources:

1. Local Knowledge Base
   → ChromaDB

2. Live / External Information
   → Tavily Web Search

The key feature is:

The system decides whether the local knowledge base is enough. If it is not enough, it falls back to web search.

That is why it is Agentic RAG.

Because smaller chunks improve retrieval accuracy.

10. chunk_size=300

Means each chunk is around 300 characters/tokens depending on splitter behavior.

The important idea:

We do not store the entire huge document as one vector.

11. chunk_overlap=50

Neighboring chunks share some text.

Why?

To preserve context at boundaries.

Example:

Chunk 1:
...Agentic RAG introduces reasoning and

Chunk 2:
reasoning and decision making...

The shared text helps avoid losing meaning.

56. 30-second explanation

“My third project is an Agentic Research Assistant using ChromaDB, Ollama and Tavily. Static AI research knowledge is stored as embeddings in a persistent ChromaDB vector database. For a question, the system retrieves relevant local chunks and uses an LLM evaluator to decide whether that context is enough. If it is sufficient, the response is generated from the local knowledge base. If not, the system automatically falls back to Tavily web search. Questions requiring current or latest information are routed directly to the web. So the overall flow is Retrieve, Evaluate, Decide, Act and Generate.”

57. 1-minute explanation

“The Agentic Research Assistant combines local RAG and live web search. First, I load an AI research knowledge file and split it into chunks using RecursiveCharacterTextSplitter. I generate embeddings with the MiniLM sentence-transformer model and store them persistently in ChromaDB.

When a user asks a static question, the query is searched semantically against ChromaDB and the top three chunks are retrieved. Instead of immediately answering like normal RAG, I added an evaluation stage where the local Llama 3.2 model checks whether the retrieved context is sufficient. If it returns YES, the answer is generated from the local knowledge. If it returns NO, the system falls back to Tavily web search.

I also detect current queries containing terms such as latest, today, news or current and route them directly to Tavily. This gives the application agentic behavior because it can evaluate information and decide what action or data source should be used.”

58. Most likely viva questions

What is Agentic RAG?

RAG enhanced with reasoning and decision-making so the system can evaluate retrieval and choose the next action or information source.

Normal RAG vs Agentic RAG?

Normal RAG follows Retrieve → Generate. Agentic RAG can Retrieve → Evaluate → Decide → Act → Generate.

Why Tavily?

To retrieve current external information when the local static knowledge base is insufficient.

Why evaluator?

Vector search always returns nearest results, which may still be irrelevant. The evaluator checks whether they actually answer the question.

Why direct-route latest questions?

A static knowledge base cannot reliably contain live information, so direct web search is more efficient.

Why ChromaDB?

Persistent semantic vector storage of documents and embeddings.

What does k=3 mean?

Retrieve the top three most similar chunks.

What is semantic search?

Retrieval based on meaning represented by embeddings rather than exact keyword matching.
